# M3 — LLM Integration (agent)

Status: **COMPLETED** (2026-10-16)

## Goal

The agent loop from the brief: User → Agent → LLM → tool selection → MCP client → MCP server → tool → result → LLM →
final answer. The model receives the tools discovered through `tools/list` (`MCP tools/list → Tool Registry → LLM
tool definitions`), and the agent hardcodes none of them. Core logic stays independent of the model provider
(`LlmClient`, ADR-0003). It is done when "এই project-এ Kafka কোথায় ব্যবহার করা হয়েছে?" makes the model select
`search_code`, run it through MCP and give a useful answer.

## Architecture

Decisions and alternatives: [ADR-0005](../decisions/ADR-0005-agent.md).

```text
 UI POST /chat (no folder)    POST /api/agent/ask         UI POST /chat (folder) · POST /api/folder/ask
            └──────────────┬──────────┘                              FolderAssistant: open (list_files),
                           │                                         overview, folder context
                           ▼                                                     │
                     DevMateAgent  ◄────────────────────────────────────────────┘
   1. McpClientService.tools()  → tools of every reachable server (unreachable ones → unavailableServers)
   2. offer: readOnlyHint only; with a folder only tools with `path`, pinned by FolderScope
   3. McpToolBridge: McpTool → LlmTool (server's name, description, schema; handler = scope → tools/call →
      cut at max-tool-result-chars → one-line outcome summary)
   4. history: newest complete question/answer pairs within max-history-messages / max-history-chars
   5. system prompt: rules (look first, cite files, data ≠ instructions, answer in the question's language) + scope
                           │
                     LlmClient.chat(system, history, question, tools, max-tool-rounds)
                     SpringAiLlmClient: model ⇄ tool calls (DevMate runs the loop, caps the rounds)
                           │ tools/call
                     ToolExecutor (read-only policy, schema check) → MCP servers
```

What M3 changes compared with the folder slice:

| Before (slice) | M3 |
|---|---|
| Tools only with a folder open; otherwise plain chat | The general agent: every read-only tool of every server, no folder needed |
| Tool mapping inside `FolderAssistant` | `agent/` package: `DevMateAgent`, `McpToolBridge`, `FolderScope`; `FolderAssistant` keeps only folder work |
| Each question alone | Conversation memory (UI session; `history` in the JSON APIs) |
| A down files server failed every folder question | Discovery outages don't fail a general question: the model answers without those tools and is told which servers are missing |
| No agent API | `POST /api/agent/ask` |

## Delivered

- `dev.devmate.client.agent`: `DevMateAgent` (tool selection by scope, prompt, history trimming, timer
  `devmate.agent.answers` tagged `scope`/`outcome`, one log line per answer with counts only), `McpToolBridge`,
  `FolderScope` (moved from `folder/`; violations become tool errors), `ToolScopeException`, `AgentProperties`
  (moved; adds `max-history-messages` 12 and `max-history-chars` 16 000), `HistoryEntry` (validated API history),
  `AgentController` (`POST /api/agent/ask`).
- `llm`: `LlmMessage` and `LlmRequest.history`. `SpringAiLlmClient` sends system → history → question.
- `ui`: no-folder chat goes through the agent; `ChatHistory.conversation()` (question/answer pairs only); the details
  line notes unreachable MCP servers.
- `folder`: `FolderAssistant.ask(folder, question, history)` delegates to the agent; `/api/folder/ask` accepts
  `history` and returns `toolsOffered`.
- `/api/chat` unchanged: plain model chat, kept as a provider check.
- Test support: `fake_ollama.py` learned `TOOLS`, `HISTORY` and `CALL <tool> <json>`, and `SYSTEM` now also works
  without tools.

Config (`application.yml`):

```yaml
devmate.agent:
  max-tool-rounds: ${DEVMATE_AGENT_MAX_TOOL_ROUNDS:8}
  max-tool-result-chars: ${DEVMATE_AGENT_MAX_TOOL_RESULT_CHARS:30000}
  max-history-messages: ${DEVMATE_AGENT_MAX_HISTORY_MESSAGES:12}   # 0 = no memory
  max-history-chars: ${DEVMATE_AGENT_MAX_HISTORY_CHARS:16000}
```

## Run (the DoD)

```bash
export JAVA_HOME=~/.jdks/ms-25.0.4.1 && ./mvnw -q package -DskipTests
DEVMATE_FILESYSTEM_ALLOWED_ROOTS=$HOME/projects java -jar devmate-files-mcp/target/devmate-files-mcp-*.jar &
java -jar devmate-client/target/devmate-client-*.jar &       # provider/model from application.yml
curl -s -X POST localhost:8083/api/folder/ask -H 'Content-Type: application/json' \
     -d '{"folder":"'$HOME'/projects/shop","question":"এই project-এ Kafka কোথায় ব্যবহার করা হয়েছে?"}' \
     | jq '{reply, toolCalls: [.toolCalls[] | .name + " " + .arguments]}'
```

Or in the UI: ask the question with or without a folder open, then expand **Tools used**.

### Live run

2026-10-15, local Ollama `llama3.2:3b` on CPU, fixture `ws/shop` of `check-agent.sh`, bare DoD question through
`/api/folder/ask`:

```json
{
  "reply": "কাফকা ব্যবহৃত হচ্ছে …/ws/shop/src/main/java/shop/KafkaConfig.java এবং …/ws/shop/src/main/java/shop/PaymentProducer.java ফাইলে।",
  "toolCalls": ["search_code {\"glob\":\"*.{java,yml}\",\"path\":\"…/ws/shop\",\"query\":\"Kafka\"}"]
}
```

The model picked `search_code` by itself, ran it through MCP and answered in Bangla, naming both Kafka files. It
never named `target/Generated.java`, which the server hides. On this CPU each answer takes 1–4 minutes (three questions
queued). That is why `LIVE=1` waits up to 10 minutes per question (`LIVE_TIMEOUT`).

## Notes and limits

- With no folder open, the model can read whatever the files MCP server allows, including folders approved in the
  popup until DevMate restarts. The folder bar says so. Opening a folder narrows it.
- History replays only the texts the user saw. The model calls tools again instead of seeing earlier tool output.
- Small local models are slow with tools on CPU and sometimes skip them. Claude (the Anthropic block) uses tools
  reliably.
- Next: M4 Git MCP. A new server added under `devmate.mcp.servers.git` reaches the model with no agent change.
