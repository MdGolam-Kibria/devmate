# M1 — Files MCP Server

Status: **COMPLETED** (2026-10-05)

## Goal

DevMate's first MCP server: sandboxed, read-only file tools that any MCP client can discover and call.

## Architecture

```text
MCP client ──Streamable HTTP──► /mcp  (Spring AI MCP server, SDK 2.0.1)
                                  │
                         OriginValidationFilter        403 on disallowed browser Origin
                                  │
                         tools/FileTools               @McpTool adapter → CallToolResult, logs tool+latency
                                  │
                         service/FileService           list / read / search: plain Java NIO, no MCP types
                                  │
                         access/FileAccessPolicy       the single sandbox gate
                                  │
                         config/FilesProperties        validated: no roots → no start
```

## Tools

| Tool          | Arguments                                   | Returns |
|---------------|---------------------------------------------|---------|
| `list_files`  | `path?` (omit → the allowed roots)          | `{path, entries[{name,path,type,size}], truncated}`, directories first |
| `read_file`   | `path`                                      | `{path, size, lineCount, content}` (UTF-8) |
| `search_code` | `query`, `path?`, `glob?` (e.g. `*.java`)   | `{query, matches[{path,line,text}], filesScanned, truncated}` |

Relative paths resolve against the first allowed root. All tools are marked `readOnlyHint=true` and
`destructiveHint=false`. Errors are `isError=true` with one line `REASON: detail`. The reasons are `INVALID_ARGUMENT`,
`NOT_FOUND`, `ACCESS_DENIED`, `NOT_A_FILE`, `NOT_A_DIRECTORY`, `TOO_LARGE`, `BINARY_FILE` and `INTERNAL_ERROR`.

## Security controls

| Threat                     | Control |
|----------------------------|---------|
| Directory traversal        | Normalise, then `toRealPath()`, then require the real path to lie inside a real root |
| Symlink escape             | Same real-path check on explicit access. Walks never follow links |
| Arbitrary FS access        | No default root: nothing is readable until a folder is configured (`DEVMATE_FILESYSTEM_ALLOWED_ROOTS`) or approved by the client (MCP roots, `allow-client-roots`, default on since 2026-10-05). With client roots off, startup fails without roots. Roots must exist and be directories |
| Probing outside sandbox    | Missing and existing outside paths give the same `ACCESS_DENIED` |
| Secrets                    | `.env*`, `*.pem`, `*.key`, `*.p12`, `*.jks`, `id_rsa*`, `.netrc`, `.npmrc`, `.pgpass`, … are never listed, read or searched |
| VCS/build noise and leaks  | `.git`, `target`, `build`, `node_modules`, `.idea`, … are excluded everywhere |
| Huge files / memory        | `max-file-size` (1 MB) enforced on the bytes actually read, so a file that grows after the size check is still caught |
| Unbounded work             | Caps on list entries (1000), search results (200), files scanned (20 000) and line length (240) |
| ReDoS                      | `search_code` is literal text only, with a 500-character query cap |
| Binary abuse               | A NUL byte in the first 8 KB means binary: refused by read and skipped by search |
| Invalid paths              | NUL bytes and invalid paths give `INVALID_ARGUMENT` |
| DNS rebinding / exposure   | Binds `127.0.0.1` by default; browser `Origin` allowlist |
| Information leakage        | Unexpected errors become `INTERNAL_ERROR: unexpected server error`. Logs carry tool name, outcome and latency only, never arguments or content |

## Run

```bash
export JAVA_HOME=~/.jdks/ms-25.0.4.1
./mvnw -pl devmate-files-mcp -am package -DskipTests
DEVMATE_FILESYSTEM_ALLOWED_ROOTS=/workspace/projects java -jar devmate-files-mcp/target/devmate-files-mcp-*.jar
# MCP endpoint: http://127.0.0.1:8091/mcp
# MCP Inspector (browser) additionally needs: DEVMATE_HTTP_ALLOWED_ORIGINS=http://localhost:6274
```

## Known limitations

- No authentication or authorisation yet (M13). Loopback binding plus the Origin check is the boundary.
- `read_file` returns whole files only (no line ranges). Files over 1 MB are refused.
- `search_code` is a linear scan: fine for single repositories, not indexed (M5 may add indexing).
- A symlink swapped between the policy check and the read (TOCTOU) is not defended against. Exploiting it requires
  write access inside the root.
- Results are JSON text, not `structuredContent` with an `outputSchema`.
